# 0008. Python bindings and documentation site

- Status: implemented
- Date: 2026-02-11
- Superseded by: `0012-mutable-python-object-model.md`, in part ("bindings are thin":
  the Python object model)
- Related specs: `specs/bindings.md`, `specs/parity.md`

## Context

Decision 0001 requires a thin PyO3 crate exposing the same functionality as
upstream `morphnet` (not API-compatible), and the goal requires zensical docs for
the bindings, deployed to GitHub Pages, including an equivalence page.

## Decision

- `crates/oxymorph-python` (excluded from the default workspace) builds the
  Python module **`oxymorph`** via maturin, exposing parsers, writers, the
  builder API, and the IR types. It contains no logic: it converts and delegates.
- The docs are a **zensical** site under `docs/` (`zensical.toml`), with an
  **Equivalence** page generated by `tools/generate_equivalence_docs.py` that
  runs upstream and oxymorph side by side and embeds the byte-identical results.
- `.github/workflows/docs.yml` builds and deploys the site to GitHub Pages on
  pushes to `main`.

## Consequences

Easier: a usable Python package and a truth-checked docs page.

Harder / owed: the equivalence page is regenerated (and committed) whenever the
port or upstream changes; the docs job is separate from the Rust CI job.
